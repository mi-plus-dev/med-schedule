## Кэширование jsDelivr: как работает

jsDelivr кэширует файлы на своих серверах, чтобы отдавать их быстро. Время обновления зависит от **типа ссылки**:

| Тип ссылки | Поведение |
|---|---|
| `@main` (ветка) | Кэш ветки. Новые коммиты могут появляться **до 12 часов** |
| `@latest` (алиас) | Кэш релизов. Обновление **до 7 дней** |
| `@v1.0.0` (тег) | Кэшируется **навсегда** (файл неизменяем) |
| `@commit-sha` | Кэшируется **навсегда** (коммит неизменяем) |

> Важно: если в репозитории есть теги, jsDelivr **отдаёт приоритет тегам**, а не коммитам. Если вы используете `@main`, теги игнорируются — работает только поведение ветки.

## Принудительная очистка кэша

Если нужно срочно обновить файл на jsDelivr — используйте **Purge API**.

### Вариант 1. Через браузер (GET)

Замените `cdn.jsdelivr.net` на `purge.jsdelivr.net` в ссылке на файл:

```
https://purge.jsdelivr.net/gh/mi-plus-dev/med-schedule@main/data/michgu/lechebnoe/4-6.json
```

Откройте эту ссылку в браузере. Если очистка запущена — вернётся JSON вида:
```json
{
  "id": "CXWDAKcejkTaas0QS",
  "status": "pending",
  "timestamp": "2024-03-21T16:33:50.876Z"
}
```

### Вариант 2. Через curl (POST, пакетно)

Можно очистить сразу несколько файлов:

```bash
curl -L -X POST \
  https://purge.jsdelivr.net \
  -H 'cache-control: no-cache' \
  -H 'content-type: application/json' \
  -d '{
    "path": [
      "/gh/mi-plus-dev/med-schedule@main/data/michgu/lechebnoe/4-6.json",
      "/gh/mi-plus-dev/med-schedule@main/data/michgu/pediatriya/4-6.json",
      "/gh/mi-plus-dev/med-schedule@main/data/michgu/stomatologiya/4-6.json"
    ]
  }'
```

### Вариант 3. Через веб-интерфейс

Откройте https://www.jsdelivr.com/tools/purge и вставьте ссылки (до 10 за раз).

> **Внимание:** не запускайте purge много раз подряд — можно получить rate limit.

## Пояснение про тег / релиз (то, что вы просили)

Разница между `@main`, `@latest` и `@v1.0.0`:

- **`@main`** — привязка к ветке. jsDelivr смотрит на «верхушку» ветки `main`. Когда вы делаете новый коммит, файл в ветке меняется, но jsDelivr может ещё до 12 часов отдавать старую версию из своего кэша.

- **`@latest`** — специальный алиас. Он указывает не на ветку, а на **последний релиз** (GitHub Release). Даже если вы сделали коммит в `main`, `@latest` его не увидит, пока вы не создадите новый релиз. И кэш релизов обновляется дольше — до 7 дней.

- **`@v1.0.0`** (конкретный тег) — указывает на конкретный **неизменяемый** коммит, помеченный тегом. Такой файл кэшируется навсегда, но и не меняется. Если вы хотите обновить данные — нужно создать **новый** тег (`v1.1.0`) и поменять ссылку в приложении.

- **`@a1b2c3d`** (коммит-хеш) — то же самое, что тег, но без создания тега. Удобно для отладки, но неудобно для продакшена (хеши не запоминаются).

**Короткий вывод:** для разработки — `@main`, для продакшена — `@vX.Y.Z`, а `@latest` лучше не использовать вообще (непредсказуемая задержка).
